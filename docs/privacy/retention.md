# Data retention (Quorum)

This note summarizes automated retention for personal data stored in Quorum. The authoritative field-level map is `docs/privacy/data-map.yml`.

## Browser auth sessions (`sessions` table)

| Item             | Policy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| When access ends | Expired sessions (`expires_at` in the past), revoked sessions (`revoked_at` set), and sessions for GitHub ids removed from `AUTH_ALLOWED_GITHUB_IDS` are rejected on every authenticated HTTP request and on new WebSocket handshakes at auth time (in place). Open chat WebSockets re-validate the database session at most once every 30 seconds on incoming messages. After revocation or expiry in the database, the socket may keep processing for up to about 30 seconds until the client sends the next message; that message triggers re-validation and closes the socket with code 1008. Idle sockets stay open until the client sends or the connection ends. Removing a GitHub id from `AUTH_ALLOWED_GITHUB_IDS` is an environment variable change and redeploy; it only affects new sockets, and Worker isolates that already accepted a connection keep the previous environment until they drain. `POST /auth/logout` may close sockets on the same Worker isolate immediately as a fast path; it is not a guarantee across isolates. |
| Row retention    | Each row is kept until **30 days** after the earlier of `expires_at` and `revoked_at` (when `revoked_at` is null, only `expires_at` applies). Rows persist until the daily purge job deletes them (production cron not deployed yet).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Purge mechanism  | Daily Worker cron (`purgeExpiredSessions` in `src/jobs/session-purge.ts`) deletes eligible rows in bounded batches. Only timestamps matching the expected ISO 8601 UTC shape are eligible.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Timestamps       | Compared as ISO 8601 UTC strings in the `YYYY-MM-DDTHH:MM:SS.sssZ` shape.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## API keys (`api_keys` table)

Open chat WebSockets that authenticated with an API key re-validate the key row at most once every 30 seconds on incoming messages. Deleting the `api_keys` row (or rotating the bootstrap key and removing the old hash) closes the socket with code 1008 on the next message after that interval, with the same idle-socket behavior as browser sessions above.

There is no in-app revocation for machine API keys yet. To rotate the bootstrap key: set a new `BOOTSTRAP_API_KEY`, deploy, then in D1 delete the `api_keys` row where `user_id IS NULL` and `key_hash` is the SHA-256 hash of the previous bootstrap secret so the old key cannot authenticate.

Account deletion and other stores follow `docs/runbooks/account-deletion.md` and per-column retention in the data map.
